# RC4 numerical-equivalence evidence

Raw results behind `docs/RC4_NUMERICAL_EQUIVALENCE_REPORT.md`. Produced by
`tools/rc4/` on one RTX 4050 Laptop (6 GB, sm_89); environment in
`environment.json`.

Path names used throughout: `cpu` = llama.cpp CPU experts (A), `cuda` =
llama.cpp native CUDA experts (B), `sabah` = Sabah (C), `sabah_prefix` = Sabah
as shipped in RC3, before the fixes. Pairs are keyed `<reference>_vs_<test>`,
so the CPU-vs-CUDA control and CUDA-vs-Sabah comparisons requested for RC4
live side by side in each file.

| file | contents |
|---|---|
| `environment.json` | commits, patch hashes, build flags, GPU, driver, run settings, the three path definitions |
| `structural_ids.json` | ids received at `MUL_MAT_ID` vs router `ffn_moe_topk`, per path |
| `op_exactness.json` | every `MUL_MAT_ID` replayed in float64 on its own inputs; also vs emulated activation quantization |
| `op_exactness_prefill_blocks0_2.json` | the per-op records for prefill blocks 0 and 2 (all four quant types) |
| `router.json` | ids (exact) and id-aligned weights per block; `cpu_vs_cuda`, `cuda_vs_sabah`, `cpu_vs_sabah`, `cuda_vs_sabah_prefix` |
| `expert_errors.json` | block 0, per slot and per (token, expert) pair, before aggregation |
| `block_errors.json` | all-block ladder: `MUL_MAT_ID` input, gate, up, SwiGLU, down, weighted, MoE out, FFN out, block out |
| `logit_errors_ladder.json` | full-vector logit metrics and top-k for the ladder runs |
| `sequential_16.json`, `sequential_64.json` | free-running greedy equivalence, run-to-run determinism |
| `error_by_token.json` | teacher-forced per-token logit error vs native CUDA |
| `margin_analysis.json`, `flip_statistics.json` | top-2 gap-shift distributions and expected-flip statistics |
| `cache_capacity_invariance.json` | 128 MiB / 512 MiB / 1 GiB hot tier, logits bitwise |
| `wrong_expert_sentinel_op.jsonl` | operation-level sentinel and tiny-tier contract results |
| `sentinel_end_to_end.json` | test-only wrong-expert build, teacher-forced, vs native CUDA |
| `api_ab.json` | `sabah serve --backend reference` vs `--backend sabah`, temperature 0, with runtime counters |
| `benchmark.json` | sustained 64-token generation for stock, CPU, native CUDA and Sabah |

Large raw tensor captures (about 1 GB per ladder run) are not committed. They
are regenerated by `tools/rc4/run_mode.py` with the capture options recorded in
the report.
